Classroom 50 Workflow

Classroom 50 is the course’s frontend for distributing assignments and checking submissions. It works with GitHub, so the skills you practice here are the same skills used in professional software development.

Before you begin

  • Create and verify a GitHub account: GitHub account setup

  • Use the GitHub username associated with your course account.

  • Accept any invitation to the course GitHub organization.

  • Install Git and a C++ compiler, or use the remote development environment described in the development-environment slides.

  • Bookmark the UWF Classroom 50 site: uwf-dsa-teaching.github.io

Web interface sign-in

The sign-in method depends on which Classroom 50 portal you are using:

  • Public hosted app (``classroom50.org``): click Sign in with GitHub and complete the standard OAuth flow.

  • Self-hosted course portal (such as ``https://uwf-dsa-teaching.github.io/``): sign in using a GitHub Personal Access Token (Classic):

    1. On the sign-in card, click Other sign-in methods, then Use a personal access token.

    2. Open the GitHub Classic Token Generator.

    3. Scroll to the bottom of the GitHub page and click Generate token.

    4. Copy the generated ghp_... token, paste it into Classroom 50, and click Sign in.

..note:

Treat the token like a password. Do not share it or commit it to a
repository.

Select your roster name carefully

  • When Classroom 50 asks you to bind your account to the course roster, select your exact name.

  • Double-check before confirming

  • Selected the wrong name:

    • contact the instructor immediately

  • Your name is not listed:

    • do not select another student’s name.

    • Contact the instructor immediately so you can be added to the roster.

Finish accepting the assignment

  1. Click Accept assignment.

  2. Classroom 50 creates a private repository named <classroom>-<assignment>-<your-username> in the GitHub organization.

  3. Open the link to the new repository on GitHub and copy its SSH or HTTPS clone URL.

Clone and develop locally

  1. Clone the assignment repository once, then work in that local directory: .. code-block:: console

    git clone REPOSITORY-URL cd ASSIGNMENT-DIRECTORY

    Experienced GitHub CLI users may use gh repo clone instead. See the GitHub CLI guide for the commands and prerequisites.

  2. The normal development loop is:

  1. Read the assignment instructions and inspect the starter code.

  2. Implement one small change at a time.

  3. Build and test locally.

  4. Check git status and review your diff.

  5. Commit meaningful checkpoints.

  6. Push your commits to GitHub.

git add .
git commit -m "Implement the requested feature"
git push

Submission and feedback

  • A push to the assignment repository is the submission event. Push before the deadline and do not wait for the last few minutes.

  • Open the repository’s Actions tab after pushing to see whether the automated checks passed or failed.

  • Read the check output carefully. A failed check is feedback about the current commit, not proof that the entire project is incorrect.

  • Fix the problem locally, commit again, and push again.

  • The instructor may use the repository, commit history, and automated test results when grading.

Good repository habits

  • Keep the repository organized and submit only the requested files.

  • Commit frequently with messages that describe the change.

  • Push regularly so that your work is backed up on GitHub.

  • Never commit generated binaries, passwords, API keys, or other secrets.

  • Ask for help by sharing the repository URL and the relevant error output; do not send a screenshot when copyable text is available.

Troubleshooting

  • The assignment repository was not created: return to the assignment link, verify that you are signed in to the correct GitHub account, and make sure any organization invitation has been accepted.

  • Permission denied when cloning or pushing: verify the remote URL and your GitHub authentication. SSH and HTTPS are both supported, but they require different authentication setup.

  • Checks are still running: wait for the GitHub Actions workflow to finish, then refresh the Actions or checks page.

  • A check failed: open the failed job, read the first relevant error, fix it locally, and push a new commit.

  • The site or repository is unavailable: preserve your local commits and contact the instructor with the assignment name, repository URL, and error message.

Classroom 50 is hosted for this course at uwf-dsa-teaching.github.io. Use that address and the course-provided assignment links. The public classroom50.org portal is a separate hosted deployment; use it only when your instructor directs you to do so.

Grading Process

  • Automated checks provide fast feedback on correctness and basic project requirements.

  • Passing all automated checks does not necessarily guarantee full credit.

  • The instructor may also evaluate design, readability, documentation, memory management, and commit history.

  • Read the assignment rubric before submitting and test edge cases yourself.

Development workflow

  • Understand the requirements.

  • Plan the data structures and algorithms before writing code.

  • Implement incrementally.

  • Test normal cases, boundary cases, and invalid input.

  • Commit and push a coherent checkpoint.

  • Review the automated feedback and iterate.
